## 📖 项目简介

**Y\.Mine · AirMind V2\.0** 是一套面向低空经济运营场景的**全域人机神经协同调度引擎**。它并非简单的数据看板，而是一个集**博弈均衡计算、空域动态定价、物流运力调度、仿生神经协同、应急响应处置、系统配置管理**于一体的**决策操作系统（Game\-OS）**。

### 🎯 核心定位


| 维度     | 说明                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| **场景** | 城市低空物流配送、应急救援、载人交通（UAM）、空域资源运营                              |
| **用户** | 低空飞行服务中心运营人员、调度指挥员、系统管理员、监管机构                             |
| **价值** | 将"空域资源"转化为可量化、可交易、可调度的"数字资产"，实现低空经济的市场化、智能化运营 |
| **原则** | 纯本地处理 · 数据主权归用户 · 零数据上传 · 敏感运营数据绝对隐私                     |

### 🧬 设计哲学

1. **博弈论底座**：基于凯利公式（Kelly Criterion）的资产配置模型，确保资源分配的长期最优增长率。
2. **仿生映射**：将人体高层大风体感（皮肤感受器 → 前庭平衡觉 → 视觉参照修正）映射为无人机传感系统（空速管 → IMU → 视觉 SLAM），实现控制逻辑的自然迁移。
3. **控制论闭环**：内置 PID 水温控制、双容串级液位、双环串级控制三大可视化实验入口，展示从"物理世界"到"数字孪生"的完整控制链路。
4. **四层底座协同**：博弈均衡（GameBase）→ 空域定价（AirCalc）→ 物流运力（AirLogistics）→ 算力调度（AirCompute），形成完整的数据流转闭环。

## 🧮 算法引擎

### 1\. 凯利公式（Kelly Criterion）

用于计算最优资产配置比例：

```Plain
f* = (b · p - q) / b

其中：
  b = 净赔率（收益/风险）
  p = 胜率（成功概率）
  q = 败率（1 - p）
```

**应用场景**：在空域时隙分配中，将"出价成功率"和"潜在收益"代入公式，计算出最优出价比例，避免过度激进或保守。

### 2\. 电池健康度（SOH）评估模型

```Plain
SOH = f(cycleCount, avgTemp, internalResistance)

简化模拟算法：
  degradation = (cycleCount / 100) * 5
  if (avgTemp > 25) degradation += ((avgTemp - 25) / 10) * 2
  SOH = 100 - min(degradation, 80)
  SOH = max(SOH, 20)
```

**状态分级**：

- 🟢 健康：SOH ≥ 80%（可执行长途/高负载任务）
- 🟡 注意：60% ≤ SOH \< 80%（仅限短途/轻载任务）
- 🔴 报废：SOH \< 60%（自动禁用，强制停飞）

### 3\. 运力匹配度算法

```Plain
匹配度 = (载重余量 × 0.4) + (续航余量 × 0.4) + (电池SOH × 0.2)
```

**输出**：对每项任务自动计算所有可用机型的匹配度，推荐 Top 3。

### 4\. 综合定价指数

```Plain
综合定价 = 基础价 × 时段系数 × 气象系数 × 拥堵系数
```

- **时段系数**：高峰 1\.2 / 平峰 1\.0 / 低谷 0\.8
- **气象系数**：晴 1\.0 / 多云 1\.05 / 雨 1\.15 / 雷暴 1\.30
- **拥堵系数**：起降点负载率 \> 70% 时，每增 10% 加价 5%

- 无需 Node\.js / npm / 构建工具（纯静态项目）

### 本地运行

```Bash
# 1. 克隆仓库
git clone https://github.com/Y-Mine/airmind-os.git
cd airmind-os

# 2. 方法一：直接用浏览器打开
open index.html

# 3. 方法二：使用 VS Code Live Server（推荐）
# 安装 Live Server 插件后，右键 index.html → Open with Live Server
```

### 部署到 GitHub Pages

```Bash
# 1. 推送代码到 GitHub 仓库
git push origin main

# 2. 在仓库 Settings → Pages 中
#    - Source: Deploy from branch
#    - Branch: main
#    - Folder: / (root)
#    - 保存

# 3. 访问 https://你的用户名.github.io/airmind-os/
```

## 📖 使用指南

### 快速上手（5 分钟体验完整流程）

1. **初始配置**：进入 **Tab 6（系统管理）**

   - 注册 2\-3 家企业（如顺丰、美团、京东）
   - 录入 4\-6 种机型（多旋翼 2 种 \+ 固定翼 2 种 \+ 倾转旋翼 2 种）
   - 调整定价参数（基础费率、气象溢价系数）
2. **创建任务**：进入 **Tab 3（物流与算力）→ 任务中心**

   - 点击"新建任务"，输入载重、距离、时效要求
   - 系统自动推荐 Top 3 机型（含电池健康度匹配）
3. **执行竞价**：进入 **Tab 2（博弈与定价）**

   - 查看凯利公式推荐的最优出价比例
   - 查看实时空域定价指数
4. **监控态势**：进入 **Tab 1（总控态势）**

   - 观察全局稳态色带（绿/黄/红）判断系统健康度
   - 查看三圈演化雷达图（风险/管控/收益）
   - 追踪四大底座数据流转动画
5. **应急响应**：进入 **Tab 5（应急调度）**

   - 输入突发事件参数（火势等级、被困人员等）
   - 查看系统自动匹配的应急策略
   - 保存记录，生成 PDF 报告

### 数据持久化说明

所有数据保存在浏览器 `localStorage` 中：

- 刷新页面 → 数据不丢失
- 关闭浏览器 → 数据不丢失
- 清除浏览器缓存 → 数据丢失（建议定期导出 JSON 备份）

**导出数据**：Tab 5 中点击"导出 JSON"即可备份全部记录。

## 🤝 贡献指南

### 开发模式：设计先行 \(Design\-First\)

本项目采用 **"设计先行"** 开发模式：

1. **Figma 设计** → 先完成 UI 设计稿，确认视觉和交互
2. **组件化开发** → 每个模块独立封装，便于维护和复用
3. **数据驱动** → UI 与数据逻辑完全解耦，便于测试和迭代

### 如何贡献

```Bash
# 1. Fork 本仓库
# 2. 创建功能分支
git checkout -b feature/your-feature-name

# 3. 开发并测试
# 4. 提交并推送
git commit -m "feat: 添加 xxx 功能"
git push origin feature/your-feature-name

# 5. 提交 Pull Request
```

### 代码规范

- **HTML**：语义化标签，BEM 命名法（如 `.card-header`、`.card-title`）
- **CSS**：使用 CSS Variables，避免硬编码颜色/尺寸
- **JavaScript**：ES6\+ 语法，函数式优先，模块化导出
